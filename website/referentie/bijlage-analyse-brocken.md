## 1. Stack and structure

### 1.1 Generator, not hand-written HTML
- Plain static HTML/CSS/JS, **generated by Python 3 scripts (standard library only)** in `_werk\`. The build system was ported from a sister site ("De Kievit Verhuizingen", itself modelled on feitsma.nl); class names are Dutch.
- Two builders, always in this order:
  1. `_werk\build_brocken.py` builds the homepage `index.html` from the skeleton `_werk\bron\index.html` plus Python string constants (`HEAD`, `HERO`, `OFFERTE`, `DIENSTEN`, `BORD`, `LIFTSPOT`, `BOOG`, `OFFERTEBLOK`, `FOOTER`, `MCTA`...). It also writes `assets\js\brocken.js`, `assets\js\blok\*.js` and `_werk\sprite.svg`.
  2. `_werk\build_paginas.py` builds every other page. It **cuts the shared parts out of the built homepage with regexes** (build_paginas.py:109-130): `<footer class="footer">…</footer>`, `<div class="mcta"…</div>`, `<section class="offerte-overlay"…</section>` (quote pill), `<section class="b-sectie b-offerte…" id="offerte"…</section>` (the big form). Header and mobile drawer come from functions in `_werk\navigatie.py` (`topbar_html()`, `drawer_html()`), so **header/footer are copied verbatim into every HTML file at build time** (no runtime include, no client-side injection).
- Page content: `_werk\paginas\<route>.html` (e.g. `_werk\paginas\diensten\verhuislift.html`, `_werk\paginas\werkgebied\tilburg.html`). First line `<!-- beschrijving: … -->` = meta description; the marker `<!-- opbouw: blokken -->` switches the page to "block layout" (hero + pill + the page's own blocks). Placeholders: `{{formulier}}`, `{{reviews:id,id}}`, `{{blok:naam|key=value}}`, `{{plaatsen}}`, `{{kv_cijfer}}`, `{{kv_aantal}}`, `{{tel}}`, `{{telhref}}`, `{{mail}}`.
- Generated page sources: `_werk\blok_plaatsen.py` (werkgebied hub + 12 town pages, from `plaatscijfers.json` (CBS/BAG open data), OSM route maps, Klantenvertellen review counts per town), `_werk\blok_klantervaringen.py` (/reviews/), `_werk\blok_veelgestelde_vragen.py` (/veelgestelde-vragen/).
- Menu tree, routes, titles, H1+lead per page, phone, KV score, domain: `_werk\navigatie.py`.
- Build-time guards: build fails on em/en dashes, on template leftovers, asserts skip link + `<main tabindex=-1>` on every page, max 158-char descriptions.

### 1.2 CSS approach ("information blocks")
- Core stylesheet `assets\css\style.css` (953 lines, heavily commented, append-only). It holds tokens (legacy names), base, buttons, header/nav/mega menu/drawer, hero, quote pill, form base, footer, mobile bar, reveal, short page header `.pk`, legal pages, a11y fixes.
- Every content section is a **"block"** with its own source file `_werk\blokken\<naam>.css` (+ optional `.js`, `.svg` icons, `.py` markup generator). Classes are BEM-ish with a per-block prefix: `.b-<naam>`, `.b-<naam>__part`, `.b-<naam>--modifier`. 56 blocks. Shared block base: `_werk\blokken\_basis.css` (tokens `--b-*`, `.b-sectie`, grounds, `.b-kopgroep/.b-label/.b-kop/.b-lead`, `.b-knoppen`, `.b-vh`). Design spec for blocks: `_werk\blokken\ONTWERP.md`.
- `_werk\css_min.py` produces:
  - `assets\css\style.min.css` = style.css + `_basis.css` + the "core" blocks `offerte`, `stemmen`, `vragen` (they are on almost every page), comments and indentation stripped only;
  - `assets\css\blok\<naam>.min.css` per other block, **linked only on pages that contain that block** (`_werk\bundels.py`, detection by `b-<naam>` class or `data-b="<naam>"` in the built HTML).
  - It also rewrites every `Nvw` in the sources to `calc(N*var(--vw))` with `--vw:min(1dvw,14.4px)`, so nothing grows beyond the 1440px layout (zoom-out-proof). Use `dvw` in source for bands that must reach the screen edge.
- **No critical/inlined CSS**: `style.min.css` is render-blocking on purpose (comment in css_min.py: async layout CSS caused CLS on a sister site). Only a tiny page-local `<style>` (`PAGINA_CSS`, `.pg-plaatsen…`) is inlined. Core CSS ~26 KB gzipped, heaviest page ~33 KB.
- Cache busting: `?v=20260917-1300` query on CSS/JS (`navigatie.BUSTER`).

## 3. Layout and rhythm

### 3.1 Container
```css
/* style.css:55 */
.wrap{max-width:var(--maxw);margin-inline:auto;padding-inline:var(--pad)}   /* 1200px, pad clamp(16px,4vw,40px) */
```
Content is capped at the 1440px look via `--vw`. Elements that must bleed to the viewport edge use `calc(-1 * max(var(--pad),(100vw - var(--maxw)) / 2 + var(--pad)))` margins (boog photo, review rail) or `left:calc(50% - 50dvw);right:calc(50% - 50dvw)` pseudo-elements (stappen band). Above 1441px such bleeding photos get rounded outer corners (`@media (min-width:1441px){.b-boog__foto{border-radius:var(--b-r-media) 0 0 var(--b-r-media)}}`).

### 3.2 Grids
- Almost every block uses a 2-column `grid-template-columns:minmax(0,Xfr) minmax(0,Yfr)` with asymmetric ratios (7/5, 5/6, 5/7, 1.1/.9, .72/1.28, 1.32/.68) and `gap:clamp(2rem,4.5vw,5rem)`.
- A few use a 12-column grid (`repeat(12,minmax(0,1fr))`): doos, plaatskaart images, plaatsfotos.
- Named `grid-template-areas` for reflow (e.g. stemmen `"kop kop" "score rail"` → `"kop" "score" "rail"`).
- Mobile = single column, image usually first (`order:-1`).
- Container queries used sparingly: `container-type:inline-size` + `cqw` for the maten arch, `@container b-voet (min-width:34rem)` in vragen.

### 3.4 Spacing scale
- Section padding: `--b-ruimte: clamp(4rem,2.8rem + 5vw,7.5rem)` (64 → 120px) top and bottom (`.b-sectie{padding-block:var(--b-ruimte)}`, _basis.css:22).
- Two light blocks in a row: second gets half top padding (_basis.css:68): `.b-sectie:is(.b-grond--wit,.b-grond--creme,.b-grond--roze) + .b-sectie:is(…){padding-top:calc(var(--b-ruimte) * .5)}`
- Heading group bottom margin `clamp(2rem,1.4rem + 2vw,3.25rem)`; label → title `1.1rem`; title → lead `1.1rem`; buttons row `margin-top:1.6rem; gap:.75rem`.
- Card padding ~`1.15-1.5rem`; gaps in card grids `clamp(.8rem,1.6vw,1.3rem)` to `clamp(1rem,2vw,1.5rem)`.
- Scroll offset: `html{scroll-padding-top:100px}`, anchored panels `scroll-margin-top:6.5rem`.

### 3.5 Radius, shadow, border conventions
- **Radius:** controls 8px, cards 15px, media 20px (`--b-r-*`); mega menu 18px; quote box 22-28px; pills/chips/buttons `999px`/`2rem`; tiny labels 4-6px.
- **Shadows:** always a two-layer "hairline + long soft negative-spread" shadow:
  - default: `0 1px 2px rgba(10,10,10,.05),0 18px 40px -24px rgba(10,10,10,.32)` (`--b-schaduw`);
  - hero media: `0 1px 2px rgba(10,10,10,.06),0 40px 70px -44px rgba(10,10,10,.55)`;
  - bordeaux or dark items use tinted shadows (`rgba(69,10,20,.45)`, `rgba(50,6,14,.3)`);
  - cut-outs use `filter:drop-shadow(0 18px 16px rgba(10,10,10,.28))`.
- **Borders:** 1px `#F4CCCD` hairlines; 1.5px `#E4E2DF` form borders; 2px ink top rule on fact lists (`border-top:2px solid var(--b-inkt)`); dashed dividers (`1px dashed var(--b-lijn)`, `2px dashed` route lines).

### 3.7 Section rhythm, grounds and shapes
- **One continuous light ground.** The `wit`, `creme` and `roze` grounds all render as `#F7F7F6`, and light sections are transparent (_basis.css:27, 47). So there are no colour seams between blocks. Colour lives *inside* blocks (bands, panels, cards).
- **Page background motifs behind all light blocks** (_basis.css:37-56):
  - `body::before`: a 16px bordeaux dot grid, masked so it fades out;

- **Depth in three layers** per block:
  - back: band, arc, outlined type or dot sheet;
  - middle: photo or transparent cut-out with drop-shadow;

### 5.3 Hover and scroll animation
- **Easing and properties:** `cubic-bezier(.22,.61,.36,1)` everywhere (`--ease`/`--b-ease`), durations .35-.9s. Only transform and opacity are animated (including the individual `rotate`/`translate`/`scale` properties).
- **Hover rules:** all hover effects sit inside `@media (hover:hover)` and are mirrored with `:focus-visible`/`:focus-within`. The common set:
  - photo zoom inside its frame (`scale(1.04-1.06)`);
  - card lift (`translateY(-4px…-6px)`) plus a deeper shadow, via an `::after` shadow layer whose opacity fades in;
  - arrow nudge (`translateX(4px)`);
  - a tilted card straightens (`rotate:0deg`);
  - orange underline wipe (`transform:scaleX(0→1)`, `transform-origin:0 50%`);
  - a cut-out rises or shifts a few px.
- **Scroll reveal** (style.css:347-357): `.js [data-reveal]{opacity:0;transform:translateY(22px);transition:opacity .7s var(--ease),transform .7s var(--ease)}` → `.in`.
  - Groups stagger 70 ms per child (`[data-reveal-groep]>*`, 16px).
  - Hero elements never start at opacity 0 (to protect LCP).

## 6. Performance, accessibility and SEO patterns

### 6.1 Performance
- **CSS/JS loading:**
  - no inlined critical CSS; one render-blocking core stylesheet (~26 KB gz) plus per-page block stylesheets;
  - all JS `defer`, split per block;
  - `?v=` cache busting, with 1-year immutable caching on `/assets/`.
- **Head order** (index.html:12-29):
  1. the `.js` class script;
  2. the font preload;
  3. hero image preloads (responsive, split by media query, `fetchpriority="high"`);
  4. stylesheets;
  5. deferred scripts.
```html
<link rel="preload" as="font" type="font/woff2" href="/assets/fonts/sora-latin.woff2" crossorigin>
<link rel="preload" as="image" href="/assets/img/hero-bg-1920.webp" imagesrcset="/assets/img/hero-bg-1280.webp 1280w, /assets/img/hero-bg-1920.webp 1920w" imagesizes="100vw" media="(min-width:761px)" fetchpriority="high">
<link rel="preload" as="image" href="/assets/img/hero-bg-mobiel.webp" media="(max-width:760px)" fetchpriority="high">
```
- **Third parties:** no preconnect, because there are no third-party fonts or CDNs. The Vimeo iframe is injected only after `load`, only at ≥761px and only without reduced motion; the poster photo stays until the player reports playback.
- **Images:** WebP everywhere, `width`/`height` on every `<img>`, lazy loading + async decoding below the fold.
- **Layout stability:** CLS guards (reserved hero cut-out height); `overflow-x:clip` instead of `hidden` to avoid creating scroll containers.
- **Other:** static SVG maps (no map JS), sprite pruning, comment-stripped CSS.

### 6.2 Accessibility
- **Skip link** (style.css:772-777): the first focusable element; fixed, slides down from `translateY(-140%)` on focus, dark bordeaux with a white outline. Its target is `<main id="top" tabindex="-1">` (no outline on main).
- **Focus:** `outline:3px solid #79242F; outline-offset:3px` on light and white on dark surfaces. Custom focus rings on inputs (3px bordeaux) and the review rail (3px orange-600); cards use `:focus-within` to mirror hover.
- **Menu:** `aria-expanded` on mega triggers; opens on keyboard focus; Escape closes. The drawer has `role="dialog" aria-modal="true"`, a focus trap and focus restore; the toggle has `aria-controls`; the scrim is `tabindex=-1 aria-hidden`.
- **FAQ:** native `<details>/<summary>` with `name` for exclusive open, so no ARIA is needed.
- **Review rail:** `role="list" tabindex="0" aria-label`; nav buttons with `aria-label` and `aria-disabled`; "Lees verder" with `aria-expanded`/`aria-controls`; the grade chip has a visually hidden "Cijfer … van de 10" (`.b-vh`).
- **Forms:**
  - labels for every field; combobox/listbox ARIA for the address autocomplete;
  - after a failed submit, an error summary with `role="alert"` gets focus and links to the fields; fields get `aria-invalid`;
  - honeypot, `autocomplete` tokens, `inputmode`.
- **WCAG specifics:** 2.2.2 is covered by a pause button for the background video; 2.4.11 by the scroll padding for the sticky mobile bar.
- **Images:** decorative images use `alt=""` with `aria-hidden` wrappers; content photos have descriptive Dutch alt text.
- **Contrast** is documented pair by pair in `_werk\contrast.txt`:
  - orange #FF5100 is never used as small text (3.27:1);
  - action orange #D24204 with white text (4.64:1);
  - muted #676767 on off-white (5.28:1);
  - bordeaux on off-white (9.30:1);
  - a dark gradient under the transparent header keeps white nav text at 4.5:1 or better over photos.
- **Text:** `text-wrap:balance` on headings, `pretty` on leads, and `overflow-wrap:break-word` on headings for long Dutch compounds.

## 8. What makes it feel modern (assessment)

1. **One continuous ground instead of striped section backgrounds.**
   - All light sections are transparent over a single off-white body.
   - The body carries very subtle, sparse line motifs and fading dot grids (`body::before/::after`, _basis.css:37-56).
   - Colour lives in objects inside sections, so the page reads as one flowing editorial surface, not a stack of coloured bands.
   - The single dark section per page gets slanted edges drawn with background gradients.
2. **Layered depth with real cut-outs.**
   - Nearly every block is "back shape / middle photo or transparent cut-out / front card".
   - Elements deliberately break edges: the mover stepping out of the form card, the team standing at the bottom of the hero, the truck on a diagonal footer panel, cards pulled up over photos with negative margins, chips overlapping legs.
   - Drop-shadows on cut-outs and two-layer "hairline + long negative-spread" shadows give a soft, premium lift.
3. **Controlled asymmetry, with one non-straight line per block.**
   - Devices: slanted `clip-path` photo crops, tilted cards (1-3°), offset stacked plates, rising steps, giant outlined numbers and words at -8°, the open logo arc.
   - They are varied so no two neighbouring blocks repeat the same device.
   - Grids are asymmetric (7/5, 5/6, .72/1.28) rather than equal columns.
4. **Confident, tight typography with one typeface.**
   - Sora variable: 700 headlines at up to 3.3rem, -0.028em tracking, `text-wrap:balance`.
   - Upright bordeaux `<em>` emphasis; tiny uppercase pill labels with an orange dot; big tabular figures.
   - An orange highlighter under the hero keyword; sentence case everywhere else.
5. **Disciplined colour system.**
   - Bordeaux, ink and off-white carry the design.
   - Orange is used only as a *signal* (dots, arcs, rules, numbers); the action button uses a darker, accessible orange.
   - Contrast is measured and documented.
6. **Tactile, domain-specific micro-interactions, all motion-safe.**
   - Cards hang from a ratchet strap and swing with a spring `linear()` easing.
   - The score ring and arcs draw themselves; the truck drives in on a perspective road; step numbers light up.
   - The radar map draws a route to the hovered town; a scroll-spy indicator slides.
   - Everything is transform/opacity only, gated by `(hover:hover)`, mirrored for keyboard focus, and fully disabled under `prefers-reduced-motion`. Content is complete without JS.
7. **Conversion scaffolding that feels like a product.**
   - An Airbnb-style pill form overlaps the hero, with a trust bar.
   - The frosted sticky header reveals the rating once you scroll.
   - The Van→Naar form row is styled like a shipping label.
   - A sticky mobile call/quote bar; phone numbers styled as brand objects.
8. **Technical polish.**
   - Zoom-proof `--vw` cap at 1440px; container units, `:has()`, `dvw` bleeds, subgrid.
   - Native `<details name>` accordion; per-page CSS/JS bundles.
   - Responsive hero preloads with `fetchpriority`; immutable caching.
   - A rich JSON-LD graph; real open data (CBS/BAG/OSM) on town pages.
