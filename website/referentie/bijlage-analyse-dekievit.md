# Design-system analysis: De Kievit Verhuizingen (website-kieviet/site)

Source repo: `C:\users\arnas\git_repos\website-kieviet\site`. This was a read-only analysis on 18-09-2026.
Live site: **https://www.de-kievit.nl/**. I checked it on 18-09-2026: it is served by Vercel with the same cache-buster (`20260909-1107`) as the repo, so the live site is this build.
All CSS citations are `site/assets/css/style.css:<line>` unless stated otherwise. Class names are Dutch; there is a glossary at the end.

## 1. Stack and structure

### Generated, not hand-written HTML
- Static HTML with one `index.html` per folder (`/particulier-verhuizen/index.html`). Paths are root-absolute (`/assets/...`) and `site/` is the webroot. Vercel runs with `trailingSlash: true`.
- The homepage `site/index.html` is generated by `site/_werk/build_kievit.py` (1039 lines of Python).
  - It reads the landing page of a different project (`~/mijnheerlijkthuis-landing/verhuizen/index.html`, a "Heerlijk Thuis" moving lander) and replaces content section by section with strings and regexes.
  - The helpers are `vervang_blok()` and `vervang1()`; each one asserts that its match occurs exactly once.
  - HTML structure and class names come from that lander; only content, colours and fonts were changed.
  - This is why the token names are misleading: `--goud` is teal, `--bruin` is navy and `.btn--groen` is yellow. See style.css:1-15.
- The other 34 pages are generated by `site/_werk/build_paginas.py` (1135 lines). It:
  - takes the page list from the menu tree `MENU` in `site/_werk/navigatie.py`. That file is the single source for the nav, the drawer, the footer legal links and the HTML sitemap.
  - cuts shared blocks out of the built homepage with regexes (`knip()`): footer, mobile CTA bar, quote pill (`.offerte-overlay`), trust strip, storage band, werkwijze, wonen/werkgebied, FAQ and lead form. The homepage effectively acts as the component library.
  - takes the page body from a hand-written file in `_werk/paginas/<slug>.html`, or from a "text layer" `_werk/paginas/teksten/<slug>.py`.
  - A text layer holds `VERVANG=[(old,new),...]` pairs that swap only words inside the shared template.
  - A skeleton check (`_skelet()`, build_paginas.py:563-630) asserts that the sequence of block-level tags and classes is identical before and after the swap, so copywriters cannot change the design.
  - writes per page: `<title>`, meta robots, description, canonical and JSON-LD. The description is taken from the first paragraph of 15+ words and cut on a sentence boundary at 158 characters or less.
  - finally writes `robots.txt` and `sitemap.xml` from the built state, listing only indexable routes.
  - `_werk/maak_404.py` builds `404.html`.
- How header and footer are shared: they are copied into every HTML file at build time; there is no runtime include.
  - The topbar and drawer HTML come from `navigatie.topbar_html()` and `navigatie.drawer_html()`, which set `aria-current="page"` per page.
  - The footer and `.mcta` are copied from the homepage with a regex.
  - The SVG sprite is copied into each page and pruned to the symbols that page uses (`_werk/snoei.py`).
- `site/.vercelignore` keeps `_werk` out of deploys. Before it was added, internal docs in `_werk` were publicly reachable.

### CSS approach
- One stylesheet: `site/assets/css/style.css` (2045 lines, 162 KB). It is heavily commented with measurements and rationale.
- `style.min.css` (110 KB, about 21 KB gzipped) is produced by `_werk/css_min.py`.
  - It strips only comments and indentation; it deliberately does not collapse whitespace around selectors.
  - Both builders call `css_min.schrijf()`, and there is a `--check` flag for pre-deploy checks.
- The stylesheet is render-blocking: `<link rel="stylesheet" href="/assets/css/style.min.css?v=20260909-1107">`, with a manual cache-buster `navigatie.BUSTER`.
- There is no critical or inlined CSS. The comments say async CSS caused CLS on another site, so it stays blocking.
- Some pages add a page-scoped `<style>` block inside `<body>` with page-prefixed classes: contact (`.ct-`), m3-calculator (`.m3`), veelgestelde-vragen (`.vgv-`), erkende-verhuizer (`.ev-`).
- Methodology: BEM-ish Dutch names (`.blok__foto`, `.hero__title--merk`), one component per section, and modifiers on sections (`.sectie--creme2`, `.ring`).
- The end of the file consists of dated "patch" blocks that override earlier rules; the file reads chronologically and the later rule wins.
- No preprocessor, no framework, no utility classes.

### JS
`site/assets/js/kievit.js` (21 KB) is loaded with `defer` on every page. build_kievit.py generates it from the homepage's inline scripts. It holds separate IIFEs:
1. Quote pill (`#ofForm`) submit: copies the Van/Naar/Datum/Woning values into the full form `#lfForm`, smooth-scrolls to `#offerte`, and focuses the name field after 600 ms.
2. Makes the date field and the "weet ik nog niet" (don't know yet) checkbox mutually exclusive.
3. Web3Forms submit via `fetch` (`https://api.web3forms.com/submit`):
   - uses a honeypot field `botcheck`;
   - sets `novalidate` only when JS runs;
   - builds an error summary list (`#lf-foutlijst`, `role="alert"`) whose links focus the field, and sets `aria-invalid` + `aria-describedby` on invalid fields;
   - replaces the form with a `.lf__done` success box.
4. The box-calculator (dozencalculator) engine. It is shared by the standalone card `.calc__card` and by the collapsible `details.lfcalc` inside the form.
   - The estimate is written to a hidden form field.
   - URL parameters (`?m2=&kamers=&...` and `?m3=`) prefill the form when the visitor comes from the calculator pages.
5. Address autocomplete on the Van/Naar fields using the PDOK Locatieserver (a free Dutch government API):
   - ARIA combobox/listbox with keyboard navigation;
   - custom validity requires a postcode plus a street or place name.
6. Navigation: mega menu on hover/focus and a mobile drawer with a focus trap. The code is identical to `NAV_JS` in navigatie.py:309-368.

Inline scripts at the end of each page's body:
- a reveal-on-scroll IntersectionObserver;
- the sticky-topbar toggle, which adds `is-stuck` when `scrollY>40`.
- The homepage also has the hero-video loader and pause button.
- `/klantervaringen/` has a "load more reviews" script that fetches `/assets/data/klantenvertellen-reviews.json`.

`<script>document.documentElement.className+=' js'</script>` sits in `<head>`, so the `.js [data-reveal]` hiding only applies when JS runs.

- **820**: the lead block stacks.

- Coloured sections (`.sectie--creme2`) keep their full padding.

### Radius, shadow and border conventions
Radius:
- `--r:18px` is the default for cards, photos and the mega panel.
- **28px** for the large conversion panels: `.of-box`, `.dozen__card`, `.calc__card`, `.leadblock__card`.
- **24px** for `.blok--navy .blok__boven`, `.blok--paneel .blok__tekst`, the `.stappen` panel and `.cert-kaart`.
- Smaller values:
  - 16px: `.uitgelicht`, `.scorepaneel`, `.vcl-*`
  - 12px: `.review`, form inputs, `.d4 li`
  - 15px: `.trust__ico`
  - 10px: figcaption chips
- **Pills (999px / 2rem)**: all buttons, chips (`.plaatsen li`, `.calc__extras label`, `.jurtoc__lijst a`), the quality-mark bar, the quote pill and badges.
- **Square**: `.dienst` service cards have no radius (sharp teal tiles with a yellow corner number).

Borders:
- 1px `var(--lijn)` (#C4E4E4) on white cards.
- 6px accent borders: `border-left:6px solid var(--goud)` on `.blok--paneel` and `.vzk-kaart`; `border-bottom:6px solid var(--geel)` on the photo in the navy block.

Shadows are soft and long with negative spread:
- `--schaduw-kaart` for small cards;
- `--schaduw` for panels;
- `--schaduw-lg` for the mega menu and the navy card;
- a coloured glow under the teal quote box: `0 24px 60px -10px rgba(0,128,122,.42)`;
- `filter:drop-shadow(...)` on transparent cut-out people and trucks.

## 5. Icons, imagery, motion, dark sections, mobile

### Icons
- An **inline SVG sprite** at the top of `<body>`: `<svg width="0" height="0" style="position:absolute" aria-hidden="true"><symbol id="...">`.
  - Icons are referenced as `<svg aria-hidden="true"><use href="#i-phone"/></svg>`.
  - The sprite is pruned per page.
  - A global `svg{fill:none}` rule applies; each symbol sets its own fill or stroke.
- UI set `i-*` (24x24): `i-wa` (WhatsApp glyph), `i-phone` (filled), `i-caret` (filled triangle, used as the arrow in every button), `i-arrow` (2.2 stroke, round), `i-star`, `i-pin`, `i-users`, `i-plan`, `i-home`, `i-check`, `i-box`. These are simple Feather/Lucide-style 2px strokes with round caps.
- Two-tone illustrative icons `ik-*` (viewBox 100): `ik-rating`, `ik-medaille`, `ik-huis`, `ik-team`.
  - Their paths use `style="fill:var(--ik-a,#3D3B3A)"` and `var(--ik-b,#DBC096)`, so a container can recolour them.
  - Example: `.trust__ico{--ik-a:#1D1D1B;--ik-b:#00807A}`.
- Brand line icons as `<img>` from `assets/img/deco/*.svg` (verhuiswagen, zakelijk, opslag, internationaal, pin, telefoon, envelop, klok...) in `.d4` lists, at 26-30px.
- The chevron, hamburger and close icons are one-off stroke SVGs. Many chevrons are CSS borders rotated 45 degrees (select arrows, drawer summary, lfcalc).
- No icon font.

### Images
- **Formats**: WebP everywhere; no AVIF, and no JPEG except `og.jpg`.
- **Widths per asset**:
  - cards: `-400/-760/-1120`
  - content: `-760/-1140` or `-800/-1200`
  - hero: `-1280/-1920/-mobiel`. The mobile file is a separate 900x1034 portrait crop, served via `<picture><source media="(max-width:760px)">`.
- **Attributes**:
  - `width`/`height` are always set;
  - `srcset` comes with precise `sizes`, for example `(min-width:901px) 380px, (min-width:561px) 44vw, calc(100vw - 60px)`;
  - below-the-fold images use `loading="lazy" decoding="async"`;
  - the hero uses `fetchpriority="high"`.
- **Framing**: `object-fit:cover` inside fixed-aspect frames (`aspect-ratio:760/435` cards, `4/5` stacked photos, `16/10` lead photo on mobile), with `object-position` tuned per image.
- **Corners**: photos have an 18px radius; service cards are square.
- **Transparent cut-outs** of real people and trucks are a core device:
  - hero trio, storage duo, venster duo, ringen duo, werkwijze truck, contact person;
  - all have `filter:drop-shadow(...)`;
  - the team put real effort into matting quality (BiRefNet + closed-form matting, documented in `_werk/BEELDREGELS.md`).
- **Overlays**:
  - the hero veil (radial + linear dark gradient) and grain noise;
  - dark figcaption chips with `backdrop-filter:blur(4px)`;
  - navy gradients in the footer.
- Archive photos are shown as grayscale polaroids.
- Decorative SVG "artifacts" (bee, honeycomb, arrows, bird, stars) are placed absolutely per section and hidden below 1280px.

## 6. Performance, accessibility, SEO

### Performance
- No critical CSS inlining. There is one render-blocking minified stylesheet (about 21 KB gzipped) and one `defer` JS file (21 KB).
- `/assets/*` gets a long cache; CSS and JS carry manual `?v=` busters.
- Preloads:
  - 2 fonts on every page;
  - on the homepage, the hero image with a `media` split (desktop srcset vs mobile file) and `fetchpriority="high"`;
  - on the homepage, the hero cut-out with `fetchpriority="low"`.
```html
<link rel="preload" as="image" href="/assets/img/hero-bg-1920.webp" imagesrcset="/assets/img/hero-bg-1280.webp 1280w, /assets/img/hero-bg-1920.webp 1920w" imagesizes="100vw" media="(min-width:761px)" fetchpriority="high">
<link rel="preload" as="image" href="/assets/img/hero-bg-mobiel.webp" media="(max-width:760px)" fetchpriority="high">
```
- No preconnect. There are no third-party runtime assets; the form and PDOK calls use fetch on demand. The build contains no analytics or tag scripts.
- Images:
  - responsive WebP with width/height;
  - lazy loading below the fold with `decoding="async"`.
- The video source is set only after load and is skipped on mobile and with reduced motion.
- CLS:
  - space is reserved for the hero cut-out on mobile;
  - topbar heights are measured (`--pk-bar`).
- The README reports local Lighthouse mobile scores of 95/100/100/100.
- Overflow guards:
  - `overflow-x:clip` on body prevents horizontal scroll;

## 8. What makes it feel modern (assessment)

1. **A restrained, owned palette with one loud accent.**
   - The body is a warm off-white (#F6F4EC) instead of pure white, with light-teal alternating bands and deep navy for weight.
   - A single saturated yellow (#FFD500) is reserved for THE action in each section.
   - Buttons carry dark text on teal and yellow (a contrast-driven choice), which reads confident rather than generic.
2. **A layered hero with real people cut out.**
   - A full-bleed photo or video sits under a radial + linear veil and film grain.
   - A transparent cut-out of the team stands in front of it.
   - The quote form physically overlaps the hero edge (`margin-top:clamp(-104px,-7.5vw,-56px)`).
   - That depth (image, veil, grain, cut-out, floating panel) is the main "premium" cue.
3. **Conversion UI that looks like a product.**
   - The pill-shaped inline form with hairline dividers (Airbnb-style search bar) and the glassy quality-mark bar.
   - Live calculators with navy result panels, m³ steppers with a sticky summary, and address autocomplete.
   - The site feels like a tool rather than a brochure.
4. **An editorial type mix.**
   - Geometric Poppins 700 headlines in dark teal, neutral Noto Sans body text.
   - A slab serif (Zilla Slab) for numerals, years, scores and the featured quote.
   - Tracked uppercase eyebrows with a leading hairline (`.label::before`) give sections a magazine-like start.
   - Fluid `clamp()` sizes everywhere.
5. **A shape language beyond rectangles.**
   - A skewed band with a matching clip-path on the photo, and an arch window with an inset outline.
   - Giant thin ring ornaments and offset colour blocks behind photos.
   - Rotated polaroids, a 24-point star badge made with clip-path, honeycomb masks, and square number tabs on sharp service tiles.
   - Varied but disciplined: only teal, navy and yellow.
6. **Soft, long, low-opacity shadows and generous radii** (`0 18px 50px -22px`; 18/24/28px radii; pills for every control), plus `backdrop-filter` glass on the sticky header and the mobile bar.
7. **Subtle, respectful motion.**
   - One easing curve; fade-up reveals with staggered groups via IntersectionObserver; image zoom on card hover.
   - The header morphs from transparent to frosted, swaps and shrinks its logo, and slides in a review badge.
   - All of it is disabled under `prefers-reduced-motion`, and the hero content is never hidden (LCP-safe).
8. **Trust built into the design system.**
   - Review scores and quality marks appear in the header, quote box, trust strip, reviews, lead form and footer.
   - They are always styled as components (score panel, glass bar, logo row) rather than pasted-in badges.
   - Reviews are quoted word for word with names and dates, and rendered with half stars.
9. **Engineering polish**:
   - responsive WebP with exact `sizes`, width/height everywhere, fetchpriority, CLS reservations;
   - strong accessibility (skip link, focus ring, focus trap, error summary, 44px targets);
   - a clean JSON-LD graph and security headers.

Things NOT to copy blindly:
- The inherited, misleading token names (`--goud` is teal, `.btn--groen` is yellow): rename them.
- `.btn--omlijnd` has no base style.
- Subpages have no OG tags.
- The breadcrumb schema has fewer levels than the visible trail.
- style.css is built as a chronological series of patches in which later rules override earlier ones, so read the whole file before extracting a component.
- The decorative artifacts are positioned per section in percentages and need `display:none` below 1280px.
